# Decisions and open questions

## Decided

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| D1 | **Subject-agnostic engine. All subject content lives in versioned packs.** | Build the foundation once and prove it on any subject | Hard-coding a first domain (the earlier PMP-first plan) |
| D2 | **Subjects are AI-built with the learner in the loop.** Hand-authored packs use the same format. | Lifelong learning means any topic; the review step guards quality | Only curated packs: doesn't scale to personal goals |
| D3 | **Prerequisites stay shallow and editable,** marked by confidence | LLMs extract prerequisite links poorly | A deep auto-generated prerequisite graph |
| D4 | **The learner's own errors reshape the pack** (Mistake Miner) | LLM-imagined mistakes don't match real learner errors; yours do | Static AI-generated mistake libraries |
| D5 | **The competency ladder:** lesson → guided → stop → next move → review | Error-finding hurts novices without prior knowledge | Straight into hidden-mistake play |
| D6 | **Coarse rubric** (identified yes/partly/no; why 0–2; fix 0–2) plus a confidence flag and deferral | LLM-human grading agreement degrades with finer rubrics; deferral improves accuracy | A fine 0–10 score |
| D7 | **Event-sourced storage in SQLite,** projections rebuildable | Formula changes without data loss; a full audit trail for the evidence | Mutable mastery tables only |
| D8 | **xAPI-shaped events** | Familiar to L&D buyers and exportable later | A custom ad-hoc log |
| D9 | **Built-in trained vs. held-out evidence design** | The only clean way to show learning with one learner | Engagement metrics only |
| D10 | **Every AI output is stamped with prompt version and model, and prompt changes go through an eval gate** | Comparable data; no silent regressions | Editing prompts freely |
| D11 | **Vanilla JS, Node, SQLite, PWA; no framework** | Solo founder; the existing stack works and is tested | React/Next rewrite |
| D12 | **Server owns cards; the client never sees answers before grading** | Integrity of the data and the evidence | Client-held scenarios (the hackathon shortcut) |
| D13 | **The trades scenarios become `packs/demo-trades`,** used in onboarding | Keeps the hackathon work and teaches the mechanic in 30 s | Dropping them |
| D14 | **Voice-first sessions, with full text mode as an option. A within-person A/B test (randomized per session) checks the choice** | Hands-free active listening suits focus; speaking the explanation is the self-explanation step. The test confirms it for you. | Text-first with voice optional |
| D15 | **Assemble, don't rebuild.** Use permissive open-source libraries for everything except the differentiators. No GPL/AGPL code in our codebase. See [`open-source-landscape.md`](open-source-landscape.md). | The core loop exists nowhere; everything around it does | Building speech, scheduling and evals ourselves |
| D16 | **Team: 5 core agents plus 2 on-call specialists (`evals-engineer`, `learning-designer`), one owning role per path; specialists never edit product code** | The gaps were independent AI-quality measurement and learning design; adding agents brings cost and blurs ownership, so on call with strict file ownership. See [team thread 0002](../team/threads/0002-is-this-the-right-team.md). | Keep 5 (QA owns evals); a standing 8–10 agent team |
| D17 | **Storage on `node:sqlite` behind `server/db.js`; forward-only migrations; append-only `event` enforced by triggers.** See [ADR 0001](../adr/0001-sqlite-storage-and-append-only-event-log.md). | No new dependency; inv. 6 enforced by the database itself | `better-sqlite3` now; code-only append-only; a migration library |
| D18 | **Event schema v1:** xAPI shape, `evt_` + ULID ids, `seq` ordering, the F1 verbs `started`/`stopped`/`explained`/`graded`/`step-shown`/`completed`; additive-only changes. **Amendment 1 (2026-10-09):** `graded.result.feedback`; `completed.result.skippedStepIds` (always present); a STOP's `stopped`/`explained`/`graded` are appended after grading in one transaction; one `step-shown` written at complete; `context.promptVersions` lists only prompts actually sent (`{}` in MOCK and for an explicit cached card); order is always `seq`. **Amendment 2 (2026-10-09, F1a re-review):** `completed.result.notGradedStepIds` (always written); `missedStepIds` excludes not-graded mistakes; caught, missed and not-graded sets are disjoint and cover every mistake; stored skip and not-graded ids are read back, never recomputed. See [ADR 0002](../adr/0002-event-schema-v1.md). | Attempts rebuild from events; no per-line request; a skipped catch must stay distinguishable from a miss, because events can't be corrected later | Full vocabulary in F1; ordering by `at`; per-line `step-shown`; per-step `step-shown` events derived on the server; re-deriving not-graded ids from `skippedStepIds` |
| D19 | **Server-owned card and attempt API** (`/api/attempts`, `…/stops`, `…/complete`); `caught: null \| {errorStepId, stepsLate, severity, correctAction}` revealed only after grading. **Amendment 1 (2026-10-09):** `GET /api/subjects` → `[{id, title}]` (the web never hard-codes a pack id); `card.subject` is the pack id; order checks use step position, not numeric id; `complete` body `{lastStepShown, skippedStepIds?}` validated (else 400); a concurrent STOP returns 409; fixture cards carry NULL `prompt_version`/`model`; the leak test ignores string-valued `error`. **Amendment 2 (2026-10-09, F1a re-review):** `missed[]` items carry `notGraded: true` (only when true; `points: 0`); the `complete` response echoes the effective `skippedStepIds`; `complete` while a STOP is in flight returns 409. See [ADR 0003](../adr/0003-server-owned-card-and-attempt-api.md). | Closes inv. 2; `attemptId` matches the event model; pack ids contain deny-listed words | `runId`; a `reveal` wrapper; keeping `/api/scenario` and `/api/grade`; `subjects` in `/api/health`; a per-attempt STOP queue; placeholder stamps such as `"none"`; a separate `notGraded[]` array; counting skips in the browser |
| D20 | **No grading in the browser;** an unreachable grader shows "Try again" and "Skip this stop". **Amendment 1 (2026-10-09):** a skipped stop is "not graded" (PM Option B): no penalty, out of max possible and the missed-critical rating, still revealed. See [ADR 0004](../adr/0004-no-grading-in-the-browser.md). | Any grading on the client needs the answers on the client; scoring a skipped catch as missed gives false feedback | Obfuscated keywords on the client; offline grading in F1; Skip scored as missed (Option A) |
| D21 | **AI gateway `server/ai/gateway.js`** with a required fallback, one `llm_call` row per call, an `x-prompt-id` header, and a prompt fingerprint that defines a "text change". **Amendment 1 (2026-10-09, clarifications):** every would-be model call goes through `run()`, MOCK included (`live: false`, outcome `mock`); an explicitly requested cached card is not an AI call (no row, no `promptVersions`); prompt modules export `VERSION` and `PROMPT = {id, system, schema, render, fingerprintInputs}`, with both fingerprints frozen by an F1a test; `server/ai/models.js` holds model, effort and deadline constants. See [ADR 0005](../adr/0005-ai-gateway-and-prompt-registry.md). | Inv. 3 and inv. 4 become structural and testable | Keeping `llm.js`; hashing the system text only; byte-identical-but-unfenced prompts |
| D22 | **Pack format v1:** pack text is always untrusted and fenced; `scoreRun` returns a rating *key* and the pack holds the labels. **Amendment 1 (2026-10-09):** the keyword grader's vocabulary moves into the pack (`copy.falseAlarmFeedback`, optional `grading.synonyms`; `mockGrade` takes a lexicon); flat `scenarios[]` with fixture filenames under `packs/<id>/scenarios/`; immutability covers `pack.json` plus every scenario file; rating keys `missedCritical`, `tier0`–`tier3`; fixture card ids `fx_<packId>_<packVersion>_<scenarioId>`. See [ADR 0006](../adr/0006-pack-format-v1.md). | Subject words leave `shared/` and `web/`; packs immutable per version; evaluative names belong to the pack | Full `ai-flow.md` §3 format now; trusted hand-authored packs; a nested `generation` object, a `cards/` directory or a `format` field; evaluative rating keys (`excellent`, `solid`, …) |
| D23 | **A plain Node eval runner through the gateway in F1, not promptfoo;** recordings replayed in `npm test`; a pinned `pending` ratchet. Amends `open-source-landscape.md` §5 item 5. Cost cap $6 per run (hard abort), $25 per month (founder F-2, 2026-10-09). See [ADR 0007](../adr/0007-plain-node-eval-runner.md). | promptfoo's provider would bypass the gateway; 76 dependencies plus telemetry | promptfoo now; Inspect AI (Python) |
